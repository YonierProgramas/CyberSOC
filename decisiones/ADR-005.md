# ADR-005 — Separación del repositorio de código y la documentación

## Contexto

El proyecto separa documentación académica y de planificación de código, configuración, pruebas y fixtures. El resumen y el plan S0 describen inicialmente una raíz común versionada con `construccion/` y `CyberSOC/`. Sin embargo, el responsable del proyecto indicó posteriormente que `construccion/` no se publicará en el repositorio y que todo el código se trabajará dentro de `CyberSOC/`.

La inspección del espacio de trabajo confirma que `.git` está en `CyberSOC/`, mientras `construccion/` es una carpeta hermana. Este ADR incorpora la corrección explícita del responsable; no reproduce la indicación anterior de subir documentación al primer commit.

Fuentes: D10 de [00-ESTADO.md](../00-ESTADO.md), [resumen general](../01-resumen-general.md), [AGENTS.md](../../AGENTS.md), [plan S0](../sprints/sprint-00-foundation/plan.md) y la instrucción del responsable registrada en esta conversación.

## Decisión

Se establece la siguiente separación operativa:

```text
Espacio de trabajo local/
├─ AGENTS.md
├─ construccion/               Documentación local, fuera del repositorio de código
│  ├─ 00-ESTADO.md
│  ├─ 01-resumen-general.md
│  ├─ decisiones/
│  ├─ ia/
│  ├─ estructuras-de-datos/
│  └─ sprints/
└─ CyberSOC/                   Raíz del repositorio Git de código
   ├─ .git/
   ├─ .github/                 Configuración de colaboración y CI
   ├─ app/                    Electron, TypeScript, React y pruebas
   ├─ engine/                 Motor Python y pruebas
   └─ contracts/              Mensajes de referencia del protocolo
```

`CyberSOC/` contendrá código, configuración, pruebas y fixtures. La documentación académica, los planes, las evidencias de sprint y los ADR permanecerán en `construccion/`, sin incorporarse al repositorio de código. Los cuatro documentos de la primera entrega ya redactados se ubican en `construccion/sprints/sprint-00-foundation/`, conforme al destino solicitado.

Las rutas de los planes se interpretarán desde el espacio de trabajo: `CyberSOC/app/` corresponde a `app/` desde la raíz Git. Las operaciones de Git y CI deberán respetar esta diferencia. La actualización general de rutas y referencias en documentos previos queda pendiente para el sprint indicado por el responsable.

## Alternativas consideradas

| Organización documentada | Resolución |
|---|---|
| Versionar `construccion/` y `CyberSOC/` bajo una misma raíz | Figura en los documentos iniciales; su publicación conjunta queda sin efecto por la corrección explícita del responsable |
| Repositorio Git en `CyberSOC/`, con `construccion/` como carpeta local hermana | Organización indicada por el responsable y observada en el espacio de trabajo |

No se ha definido una ubicación remota alternativa ni un mecanismo de respaldo para la documentación; este ADR no los presupone.

## Consecuencias

- El repositorio de código conserva separados aplicación, motor y contratos, sin documentos de sprints.
- Un clon del repositorio de código no incluye por sí solo la documentación local ni el `AGENTS.md` situado en la carpeta superior; quien trabaje con ellos necesitará acceso al espacio documental correspondiente.
- Las referencias antiguas a una raíz común deben corregirse antes de utilizarlas como instrucciones de publicación o instalación.
- La conservación y distribución de `construccion/` requieren un mecanismo independiente, todavía no especificado. Este ADR no autoriza su publicación ni modifica el seguimiento de archivos Git.

## Estado

**PROPUESTA en el registro formal D10**, que todavía conserva ese estado en `00-ESTADO.md`. La restricción operativa de no publicar `construccion/` y trabajar el código dentro de `CyberSOC/` es una instrucción explícita vigente del responsable y se respeta en este documento. Queda pendiente armonizar los documentos anteriores; no se altera su estado de aprobación con esta redacción.
